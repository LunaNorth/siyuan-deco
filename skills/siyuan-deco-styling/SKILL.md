# 轻饰笔记（siyuan-deco）块样式

轻饰笔记是**声明式**插件：样式就是块上的几个自定义属性，谁写都生效。
所以只要你能读写块属性，就能指挥它 —— **插件不需要、也没有提供任何工具**。

| 属性 | 含义 |
|---|---|
| `custom-deco-style` | 样式中文名（必须） |
| `custom-deco-card-icon` | 图标 |
| `custom-deco-card-title` | 标题 |
| `custom-deco-card-date` | 时间戳（只有「碎碎念」那个样式用） |

## 第一步：读样式清单

插件每次启动、以及用户改动自定义样式之后，都会导出：

```
data/storage/petal/siyuan-deco/ai-styles.json
```

用 `file` 工具的 read action 读它（路径相对工作区）。每条样式带这些字段：

| 字段 | 含义 |
|---|---|
| `name` | 样式中文名 —— **写进 `custom-deco-style` 的就是它** |
| `blockType` | `quote` 只适合引述块 / `block` 普通块 / `any` 用户自定义 |
| `group` | `[一级, 二级]`，一级是「引述块 / 普通块 / 自定义样式」 |
| `icon` / `defaultTitle` | 默认图标与标题 |
| `writesIcon` / `writesTitle` | 为 true 时通常要一并写入图标和标题 |
| `kind` | `builtin` 内置 / `custom` 用户自建 |

**样式名必须来自这份清单，不要自己编。** 清单很大（约 190 条），先按 `group` 或 `blockType` 筛，别整份读进来。

## 第二步：找到要改的块

用 `sql` 工具（只读）按标题定位文档，再列它的块：

```sql
SELECT id, hpath FROM blocks WHERE type='d' AND (content LIKE '%关键词%' OR hpath LIKE '%关键词%') ORDER BY updated DESC LIMIT 5;

SELECT b.id, b.type, b.subtype, b.content
FROM blocks b
WHERE b.root_id='<文档ID>' AND b.type<>'d'
ORDER BY b.sort, b.id;
```

块类型：`p` 段落 · `h` 标题 · `b` 引述块 · `c` 代码块 · `i`/`l` 列表 · `t` 表格 · `d` 文档本身。

## 第三步：读当前样式

用 `attr` 工具的 `batch-get`，块 ID 用逗号连起来：

```
{ "action": "batch-get", "ids": "<块ID1>,<块ID2>" }
```

看 `custom-deco-style` 就知道这块现在套了什么。

> 📌 **别用 SQL 的 `attributes` 表判断当前样式** —— 它有写入延迟，刚改过的块查出来可能是空的。
> 读样式一律用 `attr` 工具。

## 第四步：写样式

用 `attr` 工具的 `set`：

```
{ "action": "set", "id": "<块ID>",
  "attrs": { "custom-deco-style": "创意卡片",
             "custom-deco-card-icon": "✨",
             "custom-deco-card-title": "创意卡片" } }
```

只写 `custom-deco-style` 也能生效；清单里 `writesIcon` / `writesTitle` 为 true 时一起写更完整。
**清掉样式**：把这几个属性都设成空字符串 `""`。

## 哪些块能套，哪些不要碰

**先看这张表再动手**，套错块类型是这套东西最常翻车的地方。

| 块类型 | 能不能套 | 说明 |
|---|---|---|
| 段落 `p` | ✅ **主力** | 卡片、便签、荧光笔都是给段落用的 |
| 引述块 `b` | ✅ 但只限 `quote` 类 | 只能用「灰调引述」这类引述样式 |
| 代码块 `c` | ❌ **绝对不要套** | 见下 |
| 标题 `h` | ❌ 不要套 | 会被撑成卡片，破坏大纲观感 |
| 列表 `i` / `l` | ❌ 不要套 | 会把整段列表撑变形 |
| 表格 `t` | ❌ 不要套 | 会挤压列宽 |
| 超级块 | ❌ 不要套 | 结构复杂，很容易塌 |

> 📌 **代码块是重灾区，单独说清楚**：思源自带的代码块已经有语言标签、行号、复制按钮和
> 等宽深色底。再给它套一层卡片，会在代码上方顶出一行标题栏，和语言标签叠在一起，
> 非常难看。
>
> **即使用户明说「代码示例用终端风格」，也不要把样式套到代码块上** ——
> 直接跟他说明：思源的代码块本身已经足够清晰，再套反而会打架，建议保持原样。
> 这条优先于用户的字面要求，除非他看了说明之后仍然坚持。

## 硬规矩

1. **只写 `custom-deco-*` 属性，绝不改正文。** 不要调用任何写内容的接口。
2. **样式名必须来自清单**；写错了不会报错，只是样式悄无声息地不生效。
3. **改动超过三五个块时，先把方案列给用户看**（哪个块 → 哪个样式），确认后再写。
4. 用户说「只改样式别改文字」时，改完**抽查一两个没被套样式的段落**，确认一个字没动。

## 常见搭配（参考，不是硬规定）

| 内容 | 建议方向 |
|---|---|
| 结论 / 重点 | `重点总结`、`创意卡片` 这类 `block` 样式 |
| 注意 / 提醒 | `备忘便签`、`便利贴·柠檬`、`Callout-警告` |
| 引用别人的话 | 只对**引述块**用 `quote` 类：`灰调引述`、`气泡引述·紫` |
| 待办 | `待办事项`、`Callout-待办` |

## 出问题怎么办

- 清单读不到 → 让用户把「轻饰笔记」插件**禁用再启用**一次，它会重新导出。
- 样式写了没效果 → 先确认样式名和清单里的 `name` **完全一致**（包括「·」这类符号）。
- 自定义样式和别人对不上 → 清单是按工作区各自独立导出的，确认读的是当前工作区那份。
